# 【TikTok向け 転職ノウハウ/実用コンテンツ投稿プロンプト v2.0】

## 1. 目的
TikTokで「保存」「コメント」「共感」を最大限引き出す、**転職・就活に役立つ実用的なノウハウ・気づき**を、1〜2枚のスクリーンショットに収まる形で伝える投稿の作成。
**個人の体験談・エピソード形式ではなく、読者にとって役立つ情報・リスト・ノウハウとして提示すること。**

## 2. コンテンツの方向性（以下は参考例です。これらに限定せず、内容に応じて毎回ふさわしい切り口を自由に考えてください）

大前提として、**個人の一人称の体験談・エピソードではなく、読者にとって実際に役立つ「情報・気づき・ノウハウ」を届けるコンテンツ**にすること。以下はあくまで一例で、他にも様々な切り口があり得ます。同じパターンばかりに偏らず、投稿ごとに新しい切り口・新しいテーマを考えること。

- 転職・退職でよくある「後悔ポイント」をいくつか列挙する
- 「入社しない方がいい会社」の特徴をリスト形式で紹介する
- 面接でのNGな回答例と、代わりにこう言うと良い回答例を対比させる
- 特定の質問に対する「模範解答」を具体例とともに紹介する
- 給与交渉・年収アップ交渉のコツ
- 円満退職の進め方・退職の切り出し方
- 履歴書・職務経歴書でよくあるNGポイント
- 転職エージェントの上手な使い方・注意点
- 有給消化や引き継ぎで揉めないための立ち回り方
- 業界・職種ごとのリアルな実情（残業の多さ、将来性、向き不向き等）
- その他、転職・就活・働き方に関する、読者が「知れてよかった」と思える実用的な情報全般

**上記はあくまで例示です。投稿ごとに、その回にふさわしい新しい切り口を考えてください。**

## 3. 避けるべき要素
・犯罪的な行為 / 過度な誹謗中傷 / 明らかな差別表現 / 露骨な営業・宣伝 / 単なる愚痴 / 過度に攻撃的な内容
・実在の企業名・個人名を出さない（一般化した表現にする）
・**個人の一人称の体験談・エピソード形式にしないこと（「私は〇〇でした」という物語ではなく、「〇〇な人は要注意」「〇〇と答えるのがベター」という、読者への実用的な情報提供の形にすること）**

## 3.5 【最重要】NG例だけで終わらせない
- **NG例・失敗例・注意点を挙げる場合は、必ず「では、どうすればいいか」という改善策・OK例・具体的な言い換えをセットで示すこと。**
- 指摘・批判だけで終わる投稿は、読者にとって物足りない内容になるため絶対に避けること。
- 「①〜がNG」だけで終わらせず、「①〜がNG → こう改善すると良い」のように、**すべての項目に対応する改善策・OK例を必ず対で書くこと。**
- 一部の項目だけ改善策を書いて他は書かない、という中途半端な状態も避けること。挙げた項目すべてに改善策をセットにすること。

## 4. 感情表現
・絵文字を適度に使用（1〜2個程度）
・主な感情絵文字例：😅😭🤔😮‍💨💭🥺💸✅❌
・絵文字は文末や感情表現の直後に配置

## 5. 文字数ルール（絶対厳守）
- **全体で320〜380文字程度に収めること。** 2枚のスクリーンショットに均等に収まる分量。
- **2ブロック構成にすること。** 1ブロックあたり160〜190文字程度で均等に分ける。
- ブロック間は必ず `=====` で区切ること。
- 1文（または1項目）ごとに改行し、話題の切り替わりごとに空白行を1行はさむこと。

## 6. タイトルのルール
- 17文字以内、句読点なしの体言止め、または短いフレーズ
- 「◯選」「あるある」「NG例」など、リスト・ノウハウ感が伝わるタイトルにする
- 例：「入社前に見るべき3点」「面接NG回答集」「転職失敗あるある」

## 7. 文章構成
1. 第1ブロック：導入＋前半の項目（何についてのリスト・ノウハウか提示し、1〜2項目を紹介）
2. 第2ブロック：残りの項目＋まとめ（最後に一言、読者への軽い問いかけを添えて締める）

## 8. ハッシュタグのルール
本文の最後に、内容に関連するハッシュタグを3個つけること（多すぎても少なすぎても不可）。
例：#転職 #転職ノウハウ #就活 #面接対策

## 9. 出力フォーマット（text/markdown形式で必ず出力｜考察などは不要なので本文のみを出力）

```
■(タイトルの実際の文字列。角括弧は使わない)

(第1ブロック。160〜190文字程度)

=====

(第2ブロック。160〜190文字程度)
（最後に内容に合った絵文字を1〜2個）

#タグ1 #タグ2 #タグ3
■(タイトル再掲。角括弧は使わない。ハッシュタグ行の直後に空白行を入れず、必ず次の行に続けて書くこと)
```

※出力全体をMarkdownのコードブロック（```で囲む）にしないこと。本文をそのまま出力すること。

## 10. 出力前の最終確認チェックリスト
- [ ] **個人の一人称エピソード（「私は〇〇でした」）になっていないか？実用的なノウハウ・リスト形式になっているか？**
- [ ] **NG例・注意点を挙げた場合、そのすべてに対応する改善策・OK例をセットで示せているか？指摘だけで終わっている項目はないか？**
- [ ] 直近の投稿と切り口が重複していないか？新しい視点・新しいテーマになっているか？
- [ ] 全体で320〜380文字程度に収まっているか？実際に文字数を数えたか？**短ければ、項目をもう1つ追加するか、各項目の説明を1文ずつ補足すること（削って調整するのではなく、必ず加筆で320文字以上に届かせる）**
- [ ] 2ブロックの文字数バランスは均等か？
- [ ] 実在の企業・個人が特定できる情報を含んでいないか？
- [ ] タイトルは体言止め・フックのある短いフレーズか？
- [ ] ハッシュタグはちょうど3個か？
- [ ] 区切り線(`=====`)が1つだけ含まれているか？

## 11. 分量・形式の目安（重要）
以下は「NG→OK対比型」の約380文字の例です。これより短くならないよう意識してください。**個人の体験談ではなく、このような実用リスト形式で書くこと、そしてNG例には必ずOK例（改善策）をセットでつけることを徹底してください。**

```
■職務経歴書でやりがちなNG

採用担当者が「惜しい」と感じる書き方には共通点があります。

①NG：「営業業務を担当しました」→ 何をしたか分からず埋もれる
　OK：「月間訪問件数30件、契約達成率120%を記録」→ 数字で成果が伝わる

②NG：「チームで取り組みました」で終わる → 自分の役割が不明
　OK：「5名チームでリーダーとして進行管理を担当」→ 自分の貢献が明確になる

=====

③NG：スキル欄に「Excel・Word」とだけ記載 → 全員が書ける内容と埋もれる
　OK：「Excelで関数を用いた売上分析資料を作成」→ 活用レベルまで伝わる

④NG：フォントや余白がバラバラ → 読みにくく印象が下がる
　OK：見出しの大きさ・余白を統一し、1ページに収める → 読みやすさが向上😮‍💨

「何をしたか」ではなく「どう伝えるか」で通過率は大きく変わります。
みなさんは職務経歴書、どこに一番苦労しましたか？

#転職 #転職ノウハウ #職務経歴書
```

## 重要：出力に関する絶対禁止事項
- 文字数確認・自己チェックの結果・「✅」「❌」などのマーク・[info]や[note]のようなタグ・メタ情報を、出力に一切含めないこと。
- 出力は、実際にSNSへそのまま投稿される本文そのものである。チェックは内部で行い、その結果や過程を書き残さず、最終的な投稿本文だけを出力すること。
- 「話題は直近で使用済みなので、今回は〜の切り口で作成します」のような、話題選定の説明・言い訳・前置きの一言も、絶対に出力に含めないこと。出力の1文字目から、いきなり実際の投稿本文（タイトルや本文冒頭）が始まること。
